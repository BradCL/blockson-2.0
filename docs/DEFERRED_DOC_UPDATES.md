# Deferred documentation updates

Some docs are **frozen**: they are snapshot/teaching artifacts that read as
coherent wholes and are expensive to keep in lock-step with the code (the
learning guide is large; the tutorials carry captured screenshots and terminal
transcripts that must be re-generated by Playwright/terminal harnesses). Rather
than update them on every change — which costs effort out of proportion to the
value, since a learner doesn't need them to track the latest tweak — we let them
lag and record what they owe **here**, then reconcile in bundled passes.

**Live docs are not listed here.** `SPEC.md`, `OPERATOR.md`, and
`BLOCK_CATALOG.md` are normative/reference and are updated with the change that
affects them. This ledger is only for the frozen artifacts below.

**Prose vs. captures.** Prose deltas are cheap and can be applied any time.
**Captured artifacts** (the developer tutorial's `term/*.txt` transcripts and the
owner tutorial's PNG screenshots) are regenerated by harnesses that read the
working tree, so they should be redone **once, on a clean tree, after a batch of
related code settles** — not per change. See the post-task-C pass at the bottom.

**How to use it.** When a change lands that a frozen doc should eventually
reflect, add a one-line entry under that doc. On a reconciliation pass: load the
frozen doc once, apply every entry, update its baseline, and clear the entries.
The baseline commit gives a git fallback — `git log <baseline>..HEAD -- engine/`
is the raw delta if an entry was ever missed.

## Running a capture session (for the next bundle)

The 2026-06-30 session above cleared all then-pending debt. Keep this procedure
for the next time capture- or count-dependent debt accumulates — it regenerates
harness-produced artifacts, which is heavy and best done deliberately on a
**clean working tree**, not piecemeal:

1. Update `scripts/flows/owner-editor.js` for any editor-UI change, then re-run
   `node scripts/capture-tutorial.js scripts/flows/owner-editor.js` to regenerate
   the owner PNGs; update owner README §§3–5 prose to match.
2. `node scripts/capture-terminal-snippets.js` to regenerate the developer
   `term/*.txt`; update the developer README proof excerpt (last proof + count).
3. Write the current proof count into `02-atlas/12-testing-proofs.md` (+ any in
   `01-system-map.md`), then advance the three baselines to the then-current
   commit and clear the entries above.
